# Business mission: evidence to approved action

The signed-in **Business mission** tool restores the original research → opportunity → improvement → technical verification loop. It builds on existing campaign, creative and landing features rather than adding a separate generator.

A live mission fetches one owner-selected business HTTPS page and up to two supplied comparison pages. The collector validates every DNS answer, connects only to a validated numeric public address, verifies TLS against the original hostname, rechecks redirects, ignores proxy environment settings and bounds request duration and response size. No anonymous crawling, JavaScript execution or recursive crawl is enabled. Optional cited candidate discovery is now connected through the Business engine.

The default execution trace records source collector, HTML inspector, one budgeted Muse Spark opportunity planner, and an exact-quote evidence verifier. Optional **separate evidence research and planning roles** adds a distinct Muse Spark research request and a typed source-quote validation step before planning. The planner receives that persisted, validated handoff along with original source text and measured HTML signals. This is a real two-request role handoff when live mode is selected, using the same model in separate contexts; it is not seven independent workers or proof of independent factual verification. Sample mode uses explicitly authored fixtures for both roles.

The research artifact records model, provenance, quotes, observations, planning constraints, unknowns and validation state. Invalid research quotes stop the workflow before planning. Each call uses the same owned run and atomic budget guard; each additional call claims another workspace attempt. Optional citation repair adds at most one further request for a planner quote failure. Network/schema/research validation failures are not automatically retried. Default research handoff and repair are off. Existing single-call behavior remains available to conserve credits. Website text is untrusted data; model hypotheses are not established business facts. Each source retains URL, timestamp, content hash and measured HTML signals. A repeated unchanged request ID returns the saved result; a failed request is never automatically retried.

The research handoff is bounded to three findings and five short unknowns. Research reads up to 6,000 business-page characters and 1,400 per comparison page. To leave room for that structured handoff within the client's prompt limit, its downstream planner receives up to 4,500 business-page characters and 800 per comparison page, plus the research quotes and constraints. Default single-stage planning retains 6,000/1,400 bounds. These are partial text contexts, not full-site inspection.

Choose **Prepare campaign from mission** to pass the verified source references and proposed improvement into the campaign generator. Its saved audit records the mission ID. Subsequent landing pages remain linked through that campaign. Existing explicit review and publication rules remain in force.

After approving and publishing a linked page, choose **Verify public page & form** and consent to one synthetic inquiry. The verifier uses the operator-configured public HTTPS origin, compares the published headline with the approved draft, submits a clearly labeled test inquiry through the public form, confirms its database record, and removes that record even when the form response disconnects after storage. The report distinguishes technical before/after HTML observations from business outcomes. It retains the latest three verification results and proposes a review/reapproval cycle after failures. No automatic content correction or publication occurs.

Sample mode is explicit, makes no network or Meta requests, and uses example.org fixtures. Default repository inference gates remain off. Live missions require a real owner, public-page consent, existing workspace attempt quota, and the existing atomic app/workspace/run budget guard. One planning call, an opt-in research call, and an opt-in single citation repair are the hard workflow bounds; visuals and campaign creation remain separate explicit actions. The new two-role handoff is covered by HTTP-mocked tests; a live workflow run is not implied by those tests.

**Not claimed:** comprehensive market discovery, continuous monitoring, autonomous social publishing, measured conversion/ROI, SAM segmentation, or a complete autonomous business workforce. See ORIGINAL_PRODUCT_SCOPE.md for the connected opportunity hunter, business twin, Voice-to-Action and supervised execution controls.

## Balanced website reports and media

**Website analysis** now asks what to preserve, what to change, what already exists and why each change matters. Strength quotes are validated against sources just like opportunity quotes. Detected HTML media is explicitly separate from reviewed media.

Owners can upload a PNG/JPEG/WebP, short MP4 or PDF up to 5 MB for an explicit review. Each new live review uses one scoped request. The saved record includes textual assessment, input hash and provenance, not raw media. PDF/MP4 adapters are documentation-verified and mocked; live account verification remains pending. No automatic retry occurs on failure.

Business briefs, inquiry checklists and video shooting scripts are explicit, owner-reviewable text drafts. Download them or the combined report as Markdown or printable HTML. Video rendering, binary PDF/DOCX generation and automatic inspection of every website image/video are not implemented. Creative Studio retains image generation. Campaigns and landing pages are optional downstream actions.

## Connected original engine

The dashboard now exposes **Business engine**. Reusable business-twin context and editable voice goals feed the mission. An opt-in cited search discovers candidate sources; at most two candidate pages are fetched through the existing pinned collector. Select an opportunity to prepare an improvement directly, optionally with a generated visual, then review/edit and explicitly approve the exact draft. A separate execution action publishes the self-hosted page and performs the public-page/synthetic-form checks. Failed delivery permits a new correction draft with fresh approval; it never silently modifies an approved page. Saved receipts and reports include provenance, model/tool/human stages and technical outcomes. A direct improvement uses the existing delivery storage without requiring seven campaign posts.

Enriched research requests use smaller bounded page-text windows to accommodate context and source handoffs; original snapshots remain available for review. Voice audio is validated as mono 16-bit WAV at 16/24 kHz and capped at 60 seconds. User-initiated browser recording converts locally before explicit upload. Context/voice originals are not saved. Future monitoring and broader integrations remain in the original scope rather than being presented as finished.
